# Полный перенос ITSOFT на тестовый Docker-сервер

## Что входит в полный backup

Полный архив содержит:

- SQL-дамп MariaDB со всеми таблицами WordPress/WooCommerce;
- WordPress Core и сторонние плагины из Docker volume `app_code`;
- медиатеку, приватные дистрибутивы и другие данные из volume `local_uploads`;
- manifest, исходный URL и SHA-256 checksums.

Архив содержит пользователей, заказы, адреса, лицензионные ключи и другие закрытые данные. Он исключён из Git. Передавать его следует по SSH/SCP, хранить с правами доступа только владельцу и удалять после завершения тестирования.

Внешние платежи, Telegram, Jivo и SMTP на тестовом сервере блокируются конфигурацией WordPress.

## HTTPS на тестовом домене

До запуска команды создайте DNS `A`-запись тестового домена на публичный IPv4 сервера и откройте входящие TCP-порты `80` и `443`. Если для домена есть `AAAA`, он должен указывать на рабочий IPv6 этого же сервера; иначе удалите конфликтующую запись.

После обновления репозитория выполните:

```bash
cd /root/itsoft-project && git pull --ff-only && bash enable-https.sh test.example.com
```

Скрипт:

- сохраняет резервную копию `.env`;
- переводит URL WordPress на `https://test.example.com`;
- закрывает прямой публичный доступ к порту `8080`;
- запускает Caddy на `80/443` и автоматически получает сертификат;
- корректно заменяет старый URL в serialized-данных WordPress;
- очищает кэш WordPress и Smart Slider;
- проверяет HTTPS с самого сервера.

Сертификаты Caddy хранятся в именованном Docker volume и сохраняются при пересоздании контейнера.

## Тестовая ЮKassa

Сначала создайте в личном кабинете ЮKassa отдельный тестовый магазин. Затем на сервере:

```bash
cd /root/itsoft-project && git pull --ff-only && bash enable-yookassa-test.sh
```

Скрипт активирует только платёжный доступ к ЮKassa, устанавливает официальный plugin `yookassa` и выводит адрес настроек WooCommerce. Telegram, Jivo и внешний SMTP остаются выключены.

Для тестовой оплаты без списания денег на staging (HTTP или HTTPS):

```bash
cd /root/itsoft-project && git pull --ff-only && bash enable-staging-test-payment.sh
```

Шлюз требует одновременно `WP_ENVIRONMENT_TYPE=staging` и явный флаг окружения. В `production` он заблокирован кодом. На таком стенде должны находиться только тестовые ключи: успешный mock-платёж запускает настоящую AUTO-выдачу.

В настройках плагина подключите именно тестовый магазин. Для современной версии модуля используйте кнопку подключения магазина и выберите тестовый магазин во всплывающем окне. Если интерфейс старой версии показывает ShopID и секретный ключ, вводите только тестовые значения непосредственно в панели WordPress. Не отправляйте секрет в чат и не сохраняйте его в Git.

Минимальная проверка перед боевым включением:

1. успешная оплата тестовой картой;
2. отмена или неуспешная оплата;
3. закрытие страницы до возврата в магазин;
4. повторное HTTP-уведомление;
5. один свободный ключ на два одновременных заказа;
6. пустой пул ключей;
7. письмо покупателю и статус заказа в личном кабинете.

После теста проверьте, что заказ получил `transaction_id`, а ключ был выдан ровно один раз. Тестовый магазин не списывает реальные деньги, но его заказы нельзя считать оплаченными реальными средствами.

## 1. Создать полный backup на текущем компьютере

Из `J:\itshop`:

```powershell
.\backup-full.ps1
```

Архив и файл `.sha256` появятся в `.backups`.

## 2. Передать backup на тестовый сервер

```powershell
scp .backups\itsoft-full-ДАТА.tar.gz USER@SERVER:/opt/itsoft-backups/
```

Каталог `/opt/itsoft-backups` должен быть доступен только серверному пользователю.

## 3. Скачать Git и запустить всё одной командой

На новом Linux-сервере с установленными Git, Docker Engine и Docker Compose plugin:

```bash
git clone https://github.com/Slavko13/itshop.git /opt/itshop && cd /opt/itshop && ITSOFT_SITE_URL=http://SERVER_IP:8080 bash server-bootstrap.sh /opt/itsoft-backups/itsoft-full-ДАТА.tar.gz
```

Для приватного GitHub-репозитория удобнее заранее добавить SSH deploy key и заменить URL:

```bash
git clone git@github.com:Slavko13/itshop.git /opt/itshop && cd /opt/itshop && ITSOFT_SITE_URL=http://SERVER_IP:8080 bash server-bootstrap.sh /opt/itsoft-backups/itsoft-full-ДАТА.tar.gz
```

Команда:

1. клонирует исходники;
2. создаёт `.env` со случайными паролями БД и WordPress salt;
3. проверяет checksum полного backup;
4. создаёт и заполняет Docker volumes;
5. импортирует SQL;
6. собирает и запускает все контейнеры;
7. безопасно заменяет исходный URL в serialized WordPress data;
8. показывает состояние контейнеров.

Сайт открывается по значению `ITSOFT_SITE_URL`. Для первого теста это может быть `http://IP-СЕРВЕРА:8080`. Mailpit слушает только `127.0.0.1:8025` сервера и наружу не публикуется.

Bootstrap намеренно откажется перезаписывать непустые Docker volumes. Это защищает уже существующие данные от случайного повторного восстановления.

## Полный backup уже запущенного тестового сервера

```bash
bash server-backup.sh
```

Новый полный архив будет создан в `.backups`. Перед обновлением тестового сервера сначала выполняйте эту команду, а затем обычную code deployment-команду.
