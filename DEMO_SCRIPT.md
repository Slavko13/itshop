# Минимальное демо ITSOFT заказчику

Продолжительность: 10–15 минут.

Использовать два окна браузера:

- окно покупателя — инкогнито;
- окно администратора — обычное окно.

Все действия выполняются только локально. Платёжный метод `Тестовая оплата (без денег)` не обращается в ЮKassa и не списывает деньги.

## 0. Подготовка за 2 минуты

1. Открыть admin: `http://localhost:8080/wp-admin/`.
2. Войти:
   - логин: `itsoft_admin`;
   - пароль: `local-only-change-me`.
3. Открыть `Склад ключей` или сразу:
   `http://localhost:8080/wp-admin/admin.php?page=itsoft-license-inventory`.
4. Оставить выключенной настройку `Автоматическая выдача`.
5. В таблице связей найти товар `Windows 11 Enterprise 2024 LTSC` и посмотреть название его MANUAL-пула.
6. В блоке `Импорт individual keys` выбрать этот же пул и добавить один заведомо тестовый ключ, например:

   `DEMO-W11-2026-AAAAA-BBBBB-CCCCC`

7. Нажать `Импортировать`.
8. Ожидаемый результат: `Добавлено: 1`, а в таблице отображается только маска ключа и статус `available`.

Не использовать на демо настоящий коммерческий ключ.

## 1. Показ покупательского пути

### Поиск

1. В окне покупателя открыть `http://localhost:8080/`.
2. Найти по очереди:
   - `Винда 11`;
   - `Windows11`;
   - `Офис 2021`.
3. Показать, что товары идут выше статей, русские варианты и слитное написание распознаются.

### Регистрация покупателя

1. Открыть `http://localhost:8080/my-account/`.
2. В регистрации указать уникальный адрес, например `demo-1010@itsoft.local`.
3. После регистрации пользователь должен попасть в личный кабинет.
4. Письмо о регистрации при необходимости показать в Mailpit:
   `http://localhost:8025/`.

Если такой адрес уже использовался, изменить цифры в адресе.

### Товар и корзина

1. Открыть товар:
   `http://localhost:8080/product/windows-11-enterprise-2024-ltsc-korporativnaya/`.
2. Добавить его в корзину.
3. В корзине нажать `+`, затем `−`.
4. Ожидаемый результат: количество меняется `1 → 2 → 1`, строка товара не исчезает, итог пересчитывается автоматически.

### Checkout и mock-оплата

1. Перейти к оформлению заказа.
2. Заполнить обязательные поля.
3. Ввести один и тот же адрес в поля email и `Повторите e-mail`.
4. Для быстрой демонстрации подсказки сначала можно ввести `demo@gamil.com`, нажать предложенное исправление `demo@gmail.com`, затем повторить исправленный адрес.
5. Выбрать `Тестовая оплата (без денег)`.
6. Нажать оформление заказа.

Ожидаемый результат:

- открывается страница успешного заказа;
- заказ отмечен оплаченным локальным mock gateway;
- виден 10-значный публичный номер;
- ключ ещё не показан, потому что товар настроен в MANUAL-режиме.

Записать публичный номер — он понадобится для сравнения.

## 2. Показ административной выдачи

1. В окне администратора открыть:
   `http://localhost:8080/wp-admin/admin.php?page=wc-orders`.
2. Открыть самый свежий заказ.
3. В блоке `Лицензионные ключи` проверить:
   - тот же 10-значный публичный номер;
   - статус выдачи `Ожидает ключ`;
   - оплата подтверждена;
   - назначено `0/1` ключей.
4. Нажать `Назначить недостающие ключи`.

Ожидаемый результат:

- сообщение `Назначено: 1; уже было назначено: 0; не хватило: 0`;
- статус выдачи меняется на выданный;
- в admin показывается только маска ключа;
- один доступный ключ списывается из нужного пула.

## 3. Письмо и личный кабинет

### Письмо

1. Открыть Mailpit: `http://localhost:8025/`.
2. Найти последнее письмо покупателю.
3. Проверить:
   - публичный номер совпадает;
   - название товара совпадает;
   - в письме присутствует полный тестовый ключ.

### Личный кабинет

1. Вернуться в окно покупателя.
2. На странице обзора показать счётчики заказов и ключей.
3. Открыть `Мой аккаунт → Мои заказы` или:
   `http://localhost:8080/my-account/orders/`.
4. Открыть созданный заказ и проверить тот же публичный номер, статус выдачи и выданный ключ.
5. Открыть `Мой аккаунт → Лицензионные ключи` или:
   `http://localhost:8080/my-account/licenses/`.
6. Найти тот же товар и заказ, нажать `Показать`, затем `Скопировать`.
7. Проверить, что ключ совпадает с письмом и страницей заказа.

## 4. Сильный дополнительный тест — повторная отправка

1. Вернуться в admin заказа.
2. В блоке ключей оставить email покупателя и нажать
   `Сохранить email и отправить те же ключи`.
3. В Mailpit должно появиться новое письмо с тем же ключом.
4. На складе количество доступных ключей не должно уменьшиться повторно.

Это демонстрирует идемпотентность: повторная отправка не списывает новый ключ.

## 5. Быстрая mobile-проверка

В DevTools включить ширину 393 px либо открыть сайт на телефоне:

1. burger открывает каталог с первого нажатия;
2. `Microsoft Office` раскрывается отдельной кнопкой;
3. каталог показывает две карточки в ряд без горизонтального scroll;
4. SEO-текст находится после товаров;
5. статья и её изображения помещаются по ширине;
6. cookie-banner и обе его кнопки помещаются на экране.

Физический Android/iOS всё равно требуется для финальной приёмки.

## 6. Что честно сказать заказчику

- Склад, MANUAL/AUTO-логика, защита ключей, заказ, письмо и My Account реализованы.
- Сегодня платёж демонстрируется локальным mock gateway без денег.
- Это не доказательство работы реального callback ЮKassa.
- Настоящий тест ЮKassa будет выполнен на HTTPS staging с тестовыми реквизитами.
- SMTP, Telegram, Jivo и Яндекс.Вебмастер требуют внешних кабинетов.
- AUTO на production нельзя включать до успешного тестового платежа ЮKassa и повторного callback.

## Критерий успешного демо

Демо принято, если один и тот же заказ проходит цепочку:

`Товар → Корзина → Mock-оплата → Ожидает ключ → Ручное назначение → Email → My Account`

и во всех точках совпадают публичный номер заказа, товар и один конкретный тестовый ключ.
