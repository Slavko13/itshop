# Сборка и выкладка ITSOFT одной командой

## Что именно выкладывается

Автоматический релиз обновляет только принадлежащие проекту компоненты:

- тему `wp-content/themes/itsoft`;
- плагин `wp-content/plugins/itsoft-license-fulfillment`.

WordPress Core, WooCommerce, сторонние плагины, `uploads`, база данных, лицензионные ключи, заказы и настройки ЮKassa не входят в архив и не перезаписываются. Это позволяет безопасно обновлять существующий сайт на REG.RU без переноса рабочих данных.

## Требования

На компьютере:

- Windows PowerShell 7 или Windows PowerShell 5.1;
- Docker Desktop с запущенным локальным проектом;
- Git;
- OpenSSH (`ssh` и `scp` входят в современные версии Windows);
- доступ к серверу по SSH-ключу.

На сервере:

- уже установленный и работающий WordPress;
- SSH-доступ к каталогу сайта;
- команды `bash`, `tar` и желательно `php`;
- WP-CLI желателен, но не обязателен.

## Однократная настройка

1. Скопировать пример конфигурации:

```powershell
Copy-Item deploy/production.example.json deploy/production.local.json
```

2. Заполнить `deploy/production.local.json`:

- `host` — SSH-хост из панели REG.RU;
- `user` — SSH-пользователь;
- `port` — обычно `22`;
- `wordpressPath` — абсолютный путь к корню действующего WordPress;
- `url` — публичный HTTPS-адрес сайта;
- `identityFile` — путь к закрытому SSH-ключу на локальном компьютере.

Файл `production.local.json` исключён из Git. Пароли, ключи ЮKassa и другие секреты в него добавлять не нужно.

3. Проверить подключение:

```powershell
ssh -p 22 -i C:\Users\USER\.ssh\id_ed25519 USER@HOST
```

4. Убедиться, что `wordpressPath` содержит каталоги `wp-content/themes` и `wp-content/plugins`.

## Обычная выкладка

Сначала зафиксировать изменения в Git, затем из корня проекта выполнить одну команду:

```powershell
.\deploy.ps1 -Target production
```

Сценарий автоматически:

1. проверит Docker Compose и PHP-синтаксис;
2. проверит основные локальные страницы;
3. потребует чистое состояние Git;
4. соберёт версионный архив в `.build`;
5. загрузит архив по SCP;
6. ещё раз проверит PHP-синтаксис на сервере;
7. сохранит предыдущую тему и плагин в `~/.itsoft-backups`;
8. кратковременно включит maintenance mode, если доступен WP-CLI;
9. заменит тему и плагин;
10. сбросит объектный кеш и проверит главную страницу и каталог по HTTPS.

## Только сборка

```powershell
.\deploy.ps1 -Target production -BuildOnly
```

Архив появится в `.build`. Для диагностической сборки незакоммиченного состояния разрешён явный флаг `-AllowDirty`; для production его использовать не следует.

## Откат

После успешной выкладки команда выводит `Release id`. Для возврата файлов, которые находились на сервере до этого релиза:

```powershell
.\deploy.ps1 -Target production -Rollback RELEASE_ID
```

Откат касается темы и плагина. Если релиз содержал необратимое изменение данных, перед откатом кода необходимо отдельно восстановить согласованный backup базы. Текущий сценарий намеренно не выполняет импорт или удаление production-базы.

## Первая публикация на новый пустой сервер

Одна команда рассчитана на обновление уже работающего сайта. Для нового пустого сервера сначала один раз необходимо:

1. создать базу и пользователя в панели хостинга;
2. установить WordPress и сторонние плагины согласованных версий;
3. перенести production-базу и `uploads` через штатный backup/restore REG.RU;
4. настроить домен, HTTPS, SMTP и cron;
5. вручную ввести секреты ЮKassa и других интеграций в защищённой админке;
6. выполнить staging-проверку и только после этого переключить DNS/production.

Эти операции намеренно не автоматизированы в Git: в них участвуют рабочая база, персональные данные и секреты.
