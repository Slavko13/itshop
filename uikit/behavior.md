# IT СОФТ — поведение компонентов v3

Это UI-контракт интернет-магазина лицензий и личного кабинета. Вид компонентов задаёт `it-soft-ui-kit.html`, точные размеры — `it-soft-tokens.json`, интерфейсы — `components.json`.

## 1. Поля и формы

| Состояние | Когда возникает | Отображение и действие |
|---|---|---|
| Pristine | До взаимодействия | Label, placeholder и helper; ошибка не показывается. |
| Editing | Пользователь вводит | Сохранять draft, курсор и выделение. Пустой draft допустим во время редактирования числа. |
| Touched | После первого blur | Проверить обязательность и формат. Ошибка относится к этому полю. |
| Invalid | Проверка не прошла | `aria-invalid=true`, иконка и helper с исправлением. После ошибки проверять при изменении. |
| Validating | Проверка API в процессе | Pending-индикатор и понятный статус. Ввод при проверке поля остаётся доступным. |
| Valid | Значение прошло проверку | Убрать ошибку. Валидный формат e-mail не подтверждает владение адресом. |
| Read only | Изменение запрещено | Остаётся в Tab-порядке; значение выделяется и копируется. Named native input может отправляться в форме. |
| Disabled | Действие недоступно | Исключён из Tab-порядка; native disabled input не входит в FormData. Показать причину рядом, если она нужна. |

Правило ошибок: первый показ после blur или submit, затем обновление при вводе. Helper имеет min-height 32 px; длинное сообщение увеличивает компонент, а не обрезается. Ошибка валидации не очищает значение и не переставляет focus во время набора. Общая ошибка сервиса не окрашивает все поля как неверные.

Submit:

1. Проверить все обязательные поля и связанные значения.
2. При ошибке показать summary со ссылками и перевести focus к первой ошибке.
3. При корректных данных создать snapshot payload и перевести форму в pending. Повторный запрос заблокировать.
4. В эталонной реализации значения на время сохранения становятся read only, а кнопка — pending.
5. После успеха обновить сохранённый snapshot; после ошибки оставить draft и разрешить повтор.
6. Обновление helper не должно постоянно прерывать ввод сообщениями screen reader. Summary объявляется при submit; рядовые результаты — через `role=status`.

Ориентир для уведомления об ошибках: [WAI — Validating Input](https://www.w3.org/WAI/tutorials/forms/validation/).

### Специальные значения

| Значение | Клиентское правило | Что приходит из API / конфигурации |
|---|---|---|
| E-mail | Native email format, trim краёв; repeat совпадает с нормализованным значением. | Доступность аккаунта, серверные ошибки и verification отдельно. |
| Телефон | Позволять ввод и paste; не уничтожать пользовательский draft маской. | Страна, допустимый формат, нормализация и обязательность. +7 — только образец. |
| Пароль | Show/hide — отдельное именованное действие. Не показывать пароль неожиданно. | Policy и требования. Образец «8 символов» не задаёт политику backend. |
| Количество | На commit — целое число в min/max; при вводе допускается пустой draft. | Min/max/step, наличие и разрешённое количество. |
| Денежный диапазон | Неотрицательный ввод; пустая граница = без ограничения, 0 = реальное значение. | Валюта, ограничения, скидки и итоговая сумма. |
| Дата | Date-only ISO `YYYY-MM-DD`, сравнение границ; начало ≤ окончание. | Требуемость и допустимые границы. Native picker, без отдельного самодельного календаря. |
| Textarea | Счётчик по Unicode code points в эталоне; превышение показывает ошибку, текст сохраняется. | Limit и стратегия подсчёта должны совпадать с backend. 500 — значение демонстрации. |

Money API и вычисления используют integer minor units. Для RUB 169000 = 1690 ₽. Ввод «1 690,50» превращается в 169050; числа за пределами безопасного диапазона отклоняются. Отображение — `Intl.NumberFormat('ru-RU', {currency})`; ID, ключи и номера заказов остаются строками. Timestamp отображается в timezone магазина; date-only значение не сдвигается через UTC-конверсию.

## 2. Асинхронные состояния

- У каждого запроса есть версия / ID и snapshot входных данных. Ответ применим только к своему актуальному запросу.
- Abort / игнорирование старого ответа не позволяет прошлому поиску заменить новый. В лаборатории проверяется медленный `win` после нового `Visio`.
- Server field error отображается у своего поля и относится к тому же значению, которое проверялось. При изменении draft устаревшая ошибка снимается.
- Initial loading использует skeleton той же геометрии. Background refresh оставляет полученные данные и даёт краткий статус.
- Ошибка первой загрузки → error + retry; ошибка обновления → сохранённые данные + retry. Empty — только успешный пустой ответ.
- Ошибки UI используют публичное сообщение. Общие ответы 401/403/409/422/429/5xx переводятся адаптером в состояния, а не вставляются как технический текст. При retry-after повтор недоступен до разрешённого времени.
- Повторная отправка блокируется на клиенте; операции создания заказа и оплаты также должны иметь согласованный с backend механизм идемпотентности.

## 3. Таблицы

Использовать native `<table>` с caption и `th scope=col`. Обычная таблица не требует ARIA grid, spreadsheet-navigation или focus на каждой строке. Внутри остаются обычные checkbox, ссылки и кнопки. Ориентир: [WAI — Table Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/table/).

- Header 48 px, строка min 72 px, padding Y 8 px, cell padding X 12 px. Selection-cell без X-padding, hit-area 44 px.
- Ширины selection / order / date / status / amount / action фиксированы, product растягивается и переносит длинное название. Сумма справа и tabular numerals.
- Hover и selected окрашивают строку; keyboard focus отображается на реальном действии и через focus-within.
- Сортировка инициируется кнопкой header. `aria-sort` находится только на активной колонке. Одинаковые значения имеют стабильный tie-breaker ID.
- Checkbox выбирает показанные записи, header имеет indeterminate при частичном выборе. Checkbox не открывает заказ.
- «Открыть» передаёт orderId. Не делать всю строку кнопкой с вложенными интерактивными элементами.
- Смена фильтра и page size сбрасывает страницу на 1 и выбор; смена сортировки сохраняет выбранные ID, если они остаются в текущем наборе.
- Для лицензий те же колонки настраиваются: товар, статус выдачи, ключ и разрешённое действие копирования. Key values приходят только из разрешённого ответа API.
- Статус — `{label,tone}` из адаптера. Order status, payment status и license availability не объединять в один backend enum. Надпись «Оплачен» не является самостоятельным доказательством готовности ключа.

Pagination — отдельный контрол: page ≥ 1; предыдущая кнопка недоступна на 1, следующая — на последней странице. Пока данные новой страницы pending, повторный переход блокируется. При неизвестном totalItems использовать hasNext и не показывать выдуманное число страниц. Контекстный выбор «все» касается только показанной страницы.

## 4. Combobox и фильтры

Native select предпочтителен для простого закрытого списка. Combobox нужен для поиска среди вариантов. Query — draft; selectedId — подтверждённый выбор. Не записывать произвольный query как выбранный ID.

Editable combobox: Arrow Up/Down меняют активный вариант, Enter подтверждает, Escape закрывает popup и восстанавливает прежнее значение, Tab закрывает без нового выбора. DOM-focus остаётся в input, active option обозначается `aria-activedescendant`. Popup — listbox, варианты — option. Native клавиши редактирования текста не перехватываются. Ориентир: [WAI — Combobox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).

- Debounce 300 ms для поиска; при закрытии, смене query и commit старые результаты теряют право менять UI.
- Loading не содержит выбираемых заглушек; no-results не является option. Disabled options пропускаются.
- В лаборатории ручной commit. Автоматический выбор по blur не применяется.
- Filter draft не меняет список. «Показать» применяет валидные значения и отражает их в applied chips.
- Reset восстанавливает defaults, применяет их, очищает selection и возвращает page 1.
- Chips отражают applied, а не недоприменённый draft. Удаление одного chip применяет изменение соответствующего фильтра.
- URL-параметры для фильтров задаёт адаптер приложения. При history navigation UI восстанавливается из одного источника состояния.

## 5. Dialog, drawer и menu

Modal открывается с focus внутри, делает фон inert, блокирует фоновую прокрутку и возвращает focus на trigger при закрытии. Tab/Shift+Tab остаются внутри, Escape и видимая кнопка закрывают. Для подтверждения удаления initial focus — «Отмена». Ориентир: [WAI — Dialog Modal Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

- Max width 520 px; mobile — viewport − 32 px. Внутренняя прокрутка, actions вертикально на mobile.
- Pending блокирует повтор подтверждения, но не создаёт ловушку без возможности закрытия. Закрытие UI не объявляется отменой уже принятой сервером операции.
- Ошибка оставляет dialog открытым и восстанавливает доступность подтверждения. Исходные данные не теряются.
- Если trigger удалён после успешного действия, focus идёт к ближайшему логичному элементу.
- Drawer использует тот же modal-контракт; фильтры остаются draft до Apply.
- Menu popover не использует modal focus trap. Arrow keys обходят разрешённые действия, Enter выбирает, Escape закрывает и возвращает trigger.
- Tooltip описывает trigger, не содержит отдельную интерактивную кнопку и доступен на hover и keyboard focus.

## 6. Купон, ключ и оплата

**Купон:** trim краёв, case сохраняется; backend решает допустимость. Pending фиксирует payload и предотвращает повтор. Applied показывает подтверждённую скидку / итог из ответа; «Убрать» — отдельная мутация пересчёта. Ошибка сохраняет code.

**Ключ:** backend задаёт availability. Недоступный key не выводится, reveal/copy заблокированы. Mask — только отображение; copy использует полный raw value. Success появляется после успешного Clipboard promise. При отказе показывается инструкция: нажать «Показать», выделить значение и копировать вручную. Отказ не раскрывает скрытый ключ автоматически.

**Оплата:** method options поступают из backend. Возврат от провайдера показывает checking, затем ответ проверки состояния. Success не берётся из query-параметра страницы. Order status, payment status и выдача лицензии обновляются по своим источникам.

**Количество / цена:** границы и stock поступают из товара. При пересчёте последнее подтверждённое значение сохраняется; ошибка возвращает к нему и даёт понятный helper. Окончательная сумма, скидка и доступность оформляются по актуальному ответу backend.

## 7. Responsive и системные параметры

- Mobile < 768 px: таблица заменяется вертикальными definition-list rows из тех же данных. В DOM доступна только одна презентация; hidden версия исключена из Tab и accessibility tree.
- На 768–1029 px native table может прокручиваться внутри собственного контейнера; документ не получает горизонтальное переполнение. При ≥1030 px таблица fluid.
- Mobile input 16/24; высота 48 px и действия ≥44 px. Лицензионный read only код использует отдельный monospace style 13/20.
- Min-width:0 у значений; icons/actions flex-shrink:0. Длинные названия переносятся; raw ID / key не теряют ведущие нули.
- Z-index: base 0, dropdown 100, popover 200, backdrop 300, dialog 400, toast 500, tooltip 600. Native dialog top layer имеет собственный порядок и не подчиняется обычному z-index внешних узлов.
- Color transition 120 ms, popover 160 ms, dialog 200 ms. Reduced motion отключает движение / переходы. Pressed не сдвигает геометрию.
- У icon-only controls обязательны доступные имена; декоративные SVG имеют aria-hidden.

## 8. Границы интеграции

Лаборатория реализует взаимодействия отдельных компонентов и локальные ответы. Реальный API, платежи, авторизация, доставка и выдача ключей не подключены. Программист адаптирует события из `components.json` к существующему стеку и API. Нельзя выдавать демонстрационные статусы, условия купона, password policy, лимит textarea или количество товара за правила backend.

Для привязки нужны: схема полей и constraints, публичные field errors, page/sort/filter contract, backend statuses, available actions, amount minor units/currency, license availability, методы оплаты и idempotency policy. Эти данные поступают из проекта; UI уже содержит состояния для их корректного отображения.
