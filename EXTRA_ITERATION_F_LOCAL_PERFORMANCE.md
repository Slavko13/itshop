# Extra-итерация F — ускорение локального WordPress и корзины

Статус: реализовано, автоматическая проверка пройдена.

## Симптом

- карточка товара отвечала за `2–5 с`;
- штатное добавление WooCommerce занимало около `3,8 с`;
- после него интерфейс выполнял второй Store API запрос ещё примерно на `3,4 с`;
- визуальное ожидание кнопки могло превышать `7 с`.

## Диагностика

- база данных не была причиной: 207 запросов занимали суммарно около `0,04–0,05 с`;
- временное отключение тяжёлых плагинов почти не изменило результат, после замера все плагины включены обратно;
- основная задержка возникала при загрузке WooCommerce и WooCommerce Blocks из Windows bind-mount, содержащего тысячи PHP-файлов;
- OPcache был включён, но не устранял стоимость доступа к файлам Windows.

## Исправлено

- добавление товара объединено в один защищённый AJAX-запрос;
- ответ сразу возвращает ключи строк, количества и общий счётчик корзины;
- классическая cookie-сессия WooCommerce сохраняется, поэтому `/cart/` видит тот же товар;
- ядро WordPress и сторонние плагины один раз копируются в быстрый Linux-volume `app_code`;
- тема `itsoft` и плагин `itsoft-license-fulfillment` остаются прямыми read-only bind mounts, поэтому рабочие изменения применяются без пересборки;
- локальный OPcache настроен для Windows/Docker;
- начальное заполнение code-volume выполняется один раз и помечается файлом `.itsoft-code-seeded`.

## Результат

Контрольные замеры после прогрева:

- карточка товара: `0,28–0,33 с` вместо `3–5 с`;
- реальное добавление простого товара в Chrome: `437 мс`;
- реальное добавление вариативного товара в Chrome: `407 мс`;
- переход на `/cart/`: товар и количество сохраняются.
