# Extra-итерация C — электронные и физические товары

Статус: реализовано, ожидает ручной приёмки.

## Бизнес-правило

Тип товара и выдача ключа — независимые признаки:

- флаг WooCommerce «Виртуальный» определяет, нужен ли адрес доставки;
- связь с пулом определяет, выдаётся ли лицензионный ключ;
- товар может быть электронным с ключом, физическим без ключа или, при необходимости, физическим с ключом.

## Тестовые товары

### Электронные

- `#331` Windows 11 Enterprise 2024 LTSC (Корпоративная)
- `#333` Windows 11 IoT Enterprise 2024 LTSC (Корпоративная)

### С доставкой

- `#349` Microsoft Office 2016 Professional Plus
- `#343` Microsoft Office 2019 Professional Plus

Назначение этих четырёх товаров используется для локальной демонстрации и приёмочных тестов. Перед переносом на production тип каждого реального товара должен быть подтверждён владельцем каталога.

## Критерии приёмки

1. Корзина только с электронными товарами не требует доставки.
2. Checkout только с электронными товарами не показывает адрес и способы доставки.
3. Корзина с физическим товаром требует доставку.
4. Checkout с физическим товаром показывает адрес и способ доставки.
5. Смешанная корзина показывает доставку для заказа.
6. Связь товара с пулом не меняет его тип доставки.
7. Выдача ключей и платёжный сценарий продолжают работать.

## Что реализовано

- для `#331` и `#333` включён тип WooCommerce «Виртуальный»;
- для `#349`/вариаций `#350`, `#351` и `#343`/вариаций `#344`, `#345` сохранён физический тип;
- связь с пулом больше не превращает товар в виртуальный автоматически;
- checkout электронного заказа показывает только e-mail, подтверждение e-mail, имя, фамилию и телефон;
- checkout физического и смешанного заказа показывает адрес и способ доставки;
- «Оплата при доставке» скрывается для полностью электронного заказа и остаётся для физического/смешанного;
- добавлен отдельный smoke-тест `scripts/test-mixed-delivery.php`.

## Автоматическая проверка

Пройдены:

- `test-mixed-delivery.php` — электронная корзина без доставки, физическая и смешанная с доставкой;
- `test-cart-flow.php` — корзина электронного товара;
- `test-checkout-assurance.php` — гостевой checkout и повтор e-mail;
- `test-mock-payment-gateway.php` — тестовая оплата и AUTO-выдача;
- `test-license-order-flow.php` — полный сценарий выдачи ключей.

Контрольные изображения:

## Минимальная ручная приёмка

1. Открыть товар `#331`, добавить в корзину и перейти к оформлению: блока адреса доставки быть не должно.
2. Открыть вариацию товара `#349`, добавить её в пустую корзину и перейти к оформлению: должны быть адрес и вариант доставки.
3. К физическому товару добавить `#331`: адрес и доставка должны сохраниться.
4. Для электронного теста выбрать «Тестовая оплата (без денег)», заполнить данные покупателя и оформить заказ.
5. Проверить заказ в админке: оплата отмечена тестовой, а связанный AUTO-пул выдал ровно один ключ.

Для production владелец каталога должен отдельно подтвердить, какие товары являются электронными, а какие действительно требуют доставки.
